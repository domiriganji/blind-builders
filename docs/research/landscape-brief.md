# Landscape Brief: Tools for Blind People, April 12, 2026 to October 12, 2026 (the last six months)

Prepared October 12, 2026 for a panel deciding what new website or application should help blind people turn ideas into reality with AI: building apps and websites, starting and running companies, writing and publishing, and delegating work to AI agents. Every claim carries a source URL. Where the verification pass corrected a date or description, the corrected version is used. Items that could not be verified appear only in Appendix 7.1.

## 1. Executive summary

- The CREATE story of this window is terminal coding agents gaining screen-reader modes, led by Claude Code: `claude --ax-screen-reader` was usable on the "latest" channel from v2.1.181 (announced July 1, 2026), got its changelog entry in v2.1.208 (July 13–14), was declared "properly released" with documentation on July 20, and the November 2025 request that drove it (#11002) was closed July 21; fixes continued through v2.1.296 (October 9). https://code.claude.com/docs/en/accessibility ; https://github.com/anthropics/claude-code/issues/11002
- GitHub Copilot CLI went further on discoverability: its redesigned terminal interface (GA June 23, 2026) switches screen-reader support on automatically when a screen reader is detected; a `--screen-reader` mode has existed since October 2025 and Ctrl+Space voice dictation landed in 1.0.81 (August 27). https://github.blog/changelog/2026-06-23-copilot-cli-new-terminal-interface-is-generally-available/ ; https://raw.githubusercontent.com/github/copilot-cli/main/changelog.md
- OpenAI Codex CLI has no dedicated mode; since PR #46040 (merged September 16, 2026) it probes for a screen reader at startup and turns TUI animations off. Blind developer Taylor Arndt's request for a `--screen-reader` flag (#20489, April 30) is still open, and the Codex/ChatGPT desktop app accumulated screen-reader bugs from April to October. https://github.com/openai/codex/pull/46040 ; https://github.com/openai/codex/issues/20489
- Google moved backwards for free users: Gemini CLI, which has a `--screen-reader` flag, stopped serving free, Pro and Ultra requests on June 18, 2026 in favor of Antigravity CLI, which has no screen-reader mode; issue #6 (May 19) is still open, with blind users calling it "impossible for some tasks!" https://github.com/google-antigravity/antigravity-cli/issues/6 ; https://github.com/google-gemini/gemini-cli/discussions/27274
- Blind people are shipping real software with these agents. Jamal Mazrui's October 2026 census lists 97 apps by 40 blind or low-vision developers, 18 built with AI help; a GitHub search for blind/screen-reader accessibility repositories created since April 12 returns 81, including roughly 30 commercial-game accessibility mods, one of which a fully blind developer says was "written with heavy assistance from Anthropic's Claude." https://raw.githubusercontent.com/jamalmazrui/BlindApps/main/index.md ; https://github.com/JeanStiletto/voice-of-the-old-republic
- Peer-reviewed evidence agrees: in the ASSETS '26 paper "Bespoke Visual Assistance," five blind co-designers built 37 bespoke camera-based assistive tools in two months with the agentic tool ProgramAT (https://arxiv.org/abs/2607.21760); the CHI '26 Microsoft Research study of 16 BLV programmers found Copilot "enhanced programming efficiency and bridged accessibility gaps" while participants "struggled to convey intent, interpret AI outputs, and manage multiple views while maintaining situational awareness" (https://www.microsoft.com/en-us/research/publication/programmers-who-use-screen-readers-in-the-vibe-coding-era-adaptation-empowerment-and-new-accessibility-landscape/).
- "Tell the AI to do it for me" on a desktop is only half reliable today: in a three-week diary study, 8 blind users issued 1,258 commands to computer-use agents through the OLLA layer and the best model (GPT-5) succeeded 52.5% of the time (EMNLP 2026). https://arxiv.org/abs/2609.00524
- Because vendors shipped partial modes, blind users built the rest: hook-driven TTS and earcons (#70425), native-widget wrappers (claude-code-reader, May 5; BlindPilot, 130+ tagged versions between August 9 and October 11), the earshot plugin (October 10), a DevTools script that stops Claude Desktop unmounting the message a screen reader is reading (October 3), and agentaloud (September 2). https://github.com/anthropics/claude-code/issues/70425 ; https://github.com/serrebidev/BlindPilot ; https://github.com/unlocked-spark/claude-code-earshot ; https://github.com/thyhellcat/claude-desktop-stable-feed ; https://github.com/lpintes/agentaloud
- Vendor responsiveness is uneven and visible in the data: on anthropics/claude-code a stale bot closed #72698, #83167, #86874, #88221 and #70425 without a human reply, and an Anthropic collaborator confirmed on August 17 that built-in spoken status, humanized tool names and heading discipline are not shipped; on openai/codex a maintainer replied within a day on several threads. https://github.com/anthropics/claude-code/issues/70425 ; https://github.com/anthropics/claude-code/issues/83167 ; https://github.com/openai/codex/issues/20489
- OS-level AI in the window is for CONSUMING: Google's Guided Vision in Gemini Live (October 1, 2026, built with Aira's tester network) gives continuous camera descriptions with reframing cues; Apple previewed iOS 27 VoiceOver Image Explorer and Live Recognition in May 2026; Windows Narrator gained HID braille plug-and-play in Insider build 26300.8497 (May 22). None targets building or publishing. https://www.androidauthority.com/gemini-live-guided-vision-launch-3718122/ ; https://www.forbes.com/sites/davidphelan/2026/05/21/apple-teases-ios-27-ai-upgrades-with-major-accessibility-overhaul-to-iphone/ ; https://blogs.windows.com/windows-insider/2026/05/22/announcing-new-builds-for-22-may-2026/
- Verification is the research theme: 12 blind spreadsheet users never fully trusted GenAI output without checking, and checking cost most for charts and formatting (CHI '26, https://dl.acm.org/doi/10.1145/3772318.3790988); an audit of 1,224 AI chart descriptions shows which claims are chart-supported and which are model-supplied (https://arxiv.org/abs/2607.25021).
- Accessible data and academic publishing advanced on dated releases: py-maidr shipped 12 PyPI releases plus an agent skill that makes Claude Code, Codex, Cursor, Copilot and Gemini CLI emit accessible charts (https://github.com/xability/maidr-skill); maidr-mcp (October 1) renders sonified/braille charts inside ChatGPT and Claude via MCP Apps (https://github.com/xability/maidr-mcp); LaTeX's June 2026 release continued the Tagged PDF project (https://raw.githubusercontent.com/latex3/latex2e/main/base/doc/ltnews43.tex); JupyterLab 4.6.0 (June 18) removed a terminal focus trap and exposed toolbar states (https://github.com/jupyterlab/jupyterlab/blob/main/CHANGELOG.md).
- Creation tools reported broken: Audacity 4 is "effectively unusable by users of screen readers" per #12461 (October 12) (https://github.com/audacity/audacity/issues/12461); an [A11Y] audit of OJS/OMP 3.5, the platform behind thousands of open-access journals, began April 23 and continued into September (https://github.com/pkp/pkp-lib/issues/12601).
- Blind writers warn against the savior frame. Robert Kingett (August 5): "Just fix your fucking code. Pour some concrete. And stop trying to upgrade my body when the problem is your design." (https://raw.githubusercontent.com/rkingett/myblog/main/content/posts/the-disability-dongle.md). Andrew Leland (April 21): "I don't want people to hear this and think, 'Oh cool, AI solved accessibility, so for my next product, we don't need to think about it.'" (https://raw.githubusercontent.com/The-Focus-AI/youtube-feed/main/aboard-podcast/videos/OZiah3QUa-g.md)
- Foundations shifted underneath: NVDA 2026.1 (May 6) moved to 64-bit and broke add-on compatibility while building in MathCAT math reading; 2026.2 (August 31) added a Magnifier and NVDA+x repeat-last-spoken; 2026.3 is still in beta (beta4, October 6). Emacspeak's core has had no commit since August 26, 2024; community modules carry its agent integration. https://github.com/nvaccess/nvda/releases ; https://github.com/tvraman/emacspeak/commits/master

### 2.1 Assistive consumption apps and OS-level AI

Continuous audio descriptions, verbal reframing cues, follow-up questions while the camera stays live; launched from Gemini settings, an accessibility shortcut or the TalkBack menu; Google says it is not a mobility aid. ### 2.2 AI coding tools and their screen-reader accessibility

- **Claude Code CLI screen reader mode** (Anthropic; v2.1.181 on the latest channel June 17 and announced July 1; changelog v2.1.208 July 13–14; released July 20). Flag, env var or setting switches the TUI to linear text: labeled lines (you:, claude:, thinking:, tool:, Permission Required:, Cost:), numbered menus answered by typing a digit, y/n prompts, +/- diffs read before approval, tables as "Header: value", a terminal bell on reply end or waiting prompt, OSC 133 turn markers, deleted-text and Shift+Tab mode announcements, CLAUDE_AX_STARTUP_QUIET_MS and CLAUDE_AX_PREPARK_MS tuning, a separate CLAUDE_CODE_ACCESSIBILITY cursor for magnifiers and daltonized themes. Documented limits: not auto-enabled, costs announced only at exit, attached background sessions use the alternate screen. Relevance: the first fully documented non-visual mode in a mainstream coding agent, and the tool most blind builders in this window cite. https://code.claude.com/docs/en/accessibility ; https://github.com/anthropics/claude-code/releases/tag/v2.1.208 ; https://support.claude.com/en/articles/15924927-use-claude-code-cli-with-a-screen-reader
- **Claude Code VS Code extension screen-reader support** (Anthropic; v2.1.236 August 19; Focus-last-message v2.1.268; "Message queued." v2.1.290 October 5). Replies announced once on completion, permission requests and status changes announced, visually hidden per-turn headings, roles "You"/"Claude"/"Claude, Bash". The reporting issue #86874 was closed "not planned" by the stale bot even though the feature shipped; #97889 (September 28) reports 2.1.283 stopped echoing typed characters to VoiceOver. https://code.claude.com/docs/en/vs-code ; https://github.com/anthropics/claude-code/issues/86874 ; https://github.com/anthropics/claude-code/issues/97889

Still open or bot-closed: the transcript virtualizer unmounts the message a screen reader is reading (#83167 bot-closed September 9; root cause in #99332, October 3: "only 4 rows out of 116 were in the DOM"), the file/diff panel reads every line as "Add comment" with VoiceOver (#100911, October 9, rated Blocker), slash menu silent for NVDA (#94353), new replies not announced by NVDA (#95937). Relevance: a blind builder cannot review what the agent changed in the GUI. https://github.com/anthropics/claude-code/issues/69996 ; https://github.com/anthropics/claude-code/issues/99332 ; https://github.com/anthropics/claude-code/issues/100911

Perception is screenshots only, with no spoken narration. https://code.claude.com/docs/en/voice-dictation ; https://code.claude.com/docs/en/computer-use ; https://code.claude.com/docs/en/whats-new/2026-w36

The browser tool reads pages primarily through an accessibility tree (`read_page` with element refs, `find` by description); computer use remains screenshot-based. No screen-reader guidance appears in the Chrome docs. Relevance: an agent that can test a built web app without the human seeing the screen; accessible pages are also the pages agents handle best. https://code.claude.com/docs/en/whats-new/2026-w27 ; https://platform.claude.com/docs/en/agents-and-tools/tool-use/browser-use-tool ; https://platform.claude.com/docs/en/release-notes/overview

### 2.5 Research findings in the window

- **Programmers Who Use Screen Readers in the Vibe Coding Era** (Chen, Qiu, Wang, Wang, Yang, Microsoft Research; CHI '26, April 13, 2026). Three-phase longitudinal study of 16 BLV programmers with Copilot; recommendations include change indicators, grouped messages, a consolidated panel and a "Do Not Disturb" setting. https://www.microsoft.com/en-us/research/publication/programmers-who-use-screen-readers-in-the-vibe-coding-era-adaptation-empowerment-and-new-accessibility-landscape/
- **Bespoke Visual Assistance / ProgramAT** (Seehorn, Kim et al.; arXiv July 2026; ASSETS '26). Five BLV co-designers, two-month deployment, 37 tools across 68 iterations; ProgramAT delegates code generation to GitHub Copilot; the open-source repo requires a GitHub account, Copilot subscription, iPhone 12+ and a server. https://arxiv.org/abs/2607.21760 ; https://github.com/program-at/ProgramAT-opensource
- **Characterizing Visual Accessibility Issues in AI Developer Tools** (Haque, Csallner; August 5, 2026). 600 confirmed reports across Copilot, Cursor, Claude Code, Codex and OpenCode; three categories (AT barriers; presentation/contrast; readability/scaling/control), varying by interaction surface; maintainer engagement differs by tool. https://arxiv.org/abs/2608.05116v1
- **LipCoder** (Kim, Lee, Kim, Suh, Lee; August 31, 2026; ASSETS 2026 posters/demos). Voice-centric VS Code extension with earcons and summaries of symbols and errors; five VI programmers were numerically faster than with VS Code + Copilot + VoiceOver. https://arxiv.org/abs/2608.30793
- **Are We There Yet? (OLLA)** (Kodandaram et al.; September 1, 2026; EMNLP 2026). 52.5% success for GPT-5; failures in grounding, planning, constraint tracking and termination; interviews surfaced needs "beyond automation." https://arxiv.org/abs/2609.00524
- **Coral** (Kanchi, So, Gajos, Harvard; September 19, 2026). Browser extension generating "gists" of what changed, spoken through the existing screen reader; 8 BLV users spent less time manually checking results. https://arxiv.org/abs/2609.22799
- **"I'm Always a Little Skeptical of It"** (Perera, Ananthanarayan, Goncu, Marriott, Monash; CHI '26, April 13). 12 blind spreadsheet users; verification strategies include a second AI describing the first AI's output; errors slipped through. https://dl.acm.org/doi/10.1145/3772318.3790988
- **Querying Multimodal Scientific Papers with AI** (Chheda-Kothary, Wang, Chang, Bragg, UW/AI2; July 20, 2026; ASSETS 2026). BLV scientists asked almost double the share of figure/table queries; vague image descriptions caused abandonment; 115-query dataset. https://arxiv.org/abs/2607.18514
- **Chart-Supported or Model-Supplied?** (Eliza, Rahman; July 27, 2026; AccessViz at IEEE VIS). 1,224 descriptions tagged DIRECT/DERIVED/SPECULATIVE; structured chart context improved grounding more than adding the image. https://arxiv.org/abs/2607.25021
- **Touching or Chatting** (He et al., Utah; July 25, 2026; VIS 2026/TVCG) and **Skeleton** (Elavsky et al., CMU; July 16, 2026; VIS 2026). Tactile templates help BLV users form chart-type mental models; Skeleton is a direct-manipulation authoring environment for navigable non-visual data experiences evaluated with eight practitioners. https://arxiv.org/abs/2607.23065 ; https://arxiv.org/abs/2607.14579
- **GraphWhisper** (Das, Tarun, Mueller, Stony Brook; CHI EA '26, April 13). Chart QA from images; authors report 94% accuracy over 185 questions with 15 BLV users. https://dl.acm.org/doi/10.1145/3772363.3799030
- **Position: Assistive Agents Need Accessibility Alignment** (Hu et al.; May 13, 2026; ICML 2026). Taxonomy from 778 assistance task instances and a lifecycle pipeline. https://arxiv.org/abs/2605.13579
- **Finding the Signal in the Noise** (Kodandaram et al.; CHI '26) and **Lost in Instructions** (Padma Reddy et al.; CHI '26). AI support advice fabricates UI references that are costly to disprove by screen reader; AI-rewritten DIY instructions "often exacerbate" problems with incomplete or misleading guidance. https://dl.acm.org/doi/10.1145/3772318.3790956 ; https://dl.acm.org/doi/10.1145/3772318.3790955
- **What Gets Described Matters** (Raman, Brady; C&C '26, July 13). Six blind and low-vision artists using Midjourney v6 through sighted mediation; argues access to visual generative AI is a shared creative condition, not an accommodation. https://dl.acm.org/doi/10.1145/3803784.3807525
- **Text-based Tactile Graphics Generation** (Gao et al.; ECCV 2026; July 10 / August 20). Prompt-to-3D-printable tactile graphics with braille; user studies with BLV participants on printed outputs. https://ruihangao.github.io/Text2TactileGraphics/
- **RAVEN** (Cao, Ju, Li, Potluri, Jain, Michigan; CHI '26). Blind users modify Unity 3D scenes by natural language; code generated at runtime; evaluated with 8 BLV people and 6 developers. https://github.com/SoundabilityLab/RAVEN
- **"I Don't Trust Any Professional Research Tool"** (Khan, Seo, UIUC; CHI '26). 57 BLV researchers surveyed, 15 interviewed; nearly one-fifth could not independently do literature review or evaluate visual outputs. https://doi.org/10.1145/3772318.3791242
- **Conversational AI for Digital Accessibility** (Esposito et al.; IJHCI, May 5, 2026). 30 BLV participants; LLM agent vs screen reader for web browsing. https://www.tandfonline.com/doi/full/10.1080/10447318.2026.2659951
- **Insight** (Ansah et al., ASU; May 10, 2026). LLM overlay vs TalkBack; caveat: the study used 11 blindfolded sighted participants, not blind users. https://arxiv.org/abs/2605.09803
- **program-l mailing-list LLM analysis** (NiloofarAzizi; May 11–31, 2026; not peer-reviewed). 251 LLM discussions: Copilot 66.9%, Claude 36.3% ("rising"), Gemini 24.3%; JAWS 76 vs NVDA 52 mentions. https://raw.githubusercontent.com/NiloofarAzizi/programl-accessibility-analysis/main/docs/LLM_ACCESSIBILITY_ANALYSIS.md

## 5. Gaps: what nobody is doing, or doing badly, for blind people who want to build

1. **No agent tells a blind user when it is done, or lets them read the answer at their own pace.** Claude Code's mode is opt-in and undiscoverable (#89002), has no turn-end signal or hold-speech option (#87978), and Anthropic confirmed TTS, earcons and heading discipline are unshipped (#70425). Codex has no plain-text mode at all (#20489). https://github.com/anthropics/claude-code/issues/89002 ; https://github.com/anthropics/claude-code/issues/87978 ; https://github.com/openai/codex/issues/20489
2. **Blind builders cannot review what the agent changed in GUI surfaces.** Claude Desktop's diff panel reads "Add comment" for every line (#100911) and its transcript unmounts under the reading cursor (#99332); the Codex desktop app jumps focus to the top while generating (#22816). The CHI '26 study already named interpreting outputs and keeping situational awareness as the core unsolved problems. https://github.com/anthropics/claude-code/issues/100911 ; https://github.com/openai/codex/issues/22816 ; https://www.microsoft.com/en-us/research/publication/programmers-who-use-screen-readers-in-the-vibe-coding-era-adaptation-empowerment-and-new-accessibility-landscape/
3. **GUI "vibe-coding" builders have no demonstrated blind-user path.** Nothing was found for Bolt, v0, Base44, Replit, Jules or Devin; Lovable has only a statement of unclear scope; Cursor's first agent-panel fixes arrived in October; Antigravity CLI replaced an accessible tool with an inaccessible one for free users. https://lovable.dev/accessibility ; https://cursor.com/docs/release-notes ; https://github.com/google-antigravity/antigravity-cli/issues/6
4. **Non-visual verification of generated UI is left to the user.** Arndt keeps finding unlabeled icon buttons and missing headings in vibe-coded apps; the only remedies are community skills and three early CI gates (Ariawalk, py-tr/earshot, buyable), none validated at scale, and QuickMail's author says only a screen reader user can verify the patterns work. https://taylorarndt.substack.com/p/i-keep-testing-vibe-coded-apps-here ; https://github.com/AndreHogberg/ariawalk-action ; https://raw.githubusercontent.com/kellylford/QuickMail/main/docs/planning/the-quickmail-story.md

## 6. Research on blind people's distinct perceptual and cognitive strengths, and what is myth versus evidence

Evidence found in or adjacent to the window:

- Expert echolocators accumulate spatial evidence across repeated clicks: four blind experts outperformed 21 sighted novices and improved as more clicks were presented, with EEG decoding tracking performance in some experts. Published April 6, 2026, six days before the window (eNeuro). The sample is four people. https://www.eneuro.org/content/13/4/ENEURO.0342-25.2026
- Late-blind adults with sensorineural hearing loss outperformed sighted peers on digit span (working memory) and temporal modulation tasks, while differences in spectral resolution, speech recognition and ERP measures were mostly absent; the authors describe the advantages as selective and partly constrained by hearing loss (Frontiers in Aging Neuroscience, 2026; exact date unconfirmed). https://www.frontiersin.org/journals/aging-neuroscience/articles/10.3389/fnagi.2026.1769582/abstract
- Tactile chart templates help BLV participants form mental models of complex chart types, which supports later LLM-mediated exploration (12 participants, VIS 2026). https://arxiv.org/abs/2607.23065
- On pin-array displays, audio cues help users grasp spatial relationships and reorient; audio interaction should stay simple so hands remain on the display (11 VI participants, EuroHaptics 2026). https://link.springer.com/chapter/10.1007/978-3-032-32230-2_22
- Fast listening is a practitioner fact in the community record: "Blind and low-vision users commonly listen at 300–500+ words per minute." Classic pre-2026 studies on ultra-fast speech comprehension in blind listeners are the usual citation base and were not re-verified by this scan. https://github.com/anthropics/claude-code/issues/71471
- Blind scientists direct their AI effort at access (figures and tables), not at a different kind of science; the query asymmetry reflects what sighted peers get for free. https://arxiv.org/abs/2607.18514

Sober note on myth versus evidence:

- The advantages that replicate are selective (temporal processing, working memory, trained echolocation) and come from small samples; they do not add up to a general "sixth sense" and do not survive concurrent hearing loss in the broader measures. Products should design for dense, fast, well-structured audio while keeping braille and haptic redundancy. https://www.frontiersin.org/journals/aging-neuroscience/articles/10.3389/fnagi.2026.1769582/abstract
- Studies that use blindfolded sighted proxies do not establish benefits for blind users: Insight's "beats TalkBack" result came from 11 sighted participants aged 20–30. https://arxiv.org/abs/2605.09803
- The real distinct capacity documented in this window is verification discipline under uncertainty, not perception: blind users never trusted GenAI output unchecked and developed layered strategies, at a cost in time that products should budget for rather than romanticize. https://dl.acm.org/doi/10.1145/3772318.3790988
- Blind writers explicitly reject body-upgrade and superpower framings ("stop trying to upgrade my body when the problem is your design"); the panel should treat strengths as design inputs, not as marketing. https://raw.githubusercontent.com/rkingett/myblog/main/content/posts/the-disability-dongle.md
- A widely repeated "UIST 2026 best paper" on grid-based coding for blind programmers is in fact a 2022 paper (Ehtesham-Ul-Haque, Monsur, Billah; UIST '22 Best Paper); it remains relevant (12 BLV programmers navigated faster in a 2D grid) but is not new evidence. https://dl.acm.org/doi/abs/10.1145/3526113.3545620

### 7.2 Method and its limits

The underlying scan was performed by seven scouting passes plus a verification pass between October 10 and 12, 2026, under a shared web-search budget that was exhausted partway through (several scouts ran zero web searches) and inside a sandbox whose egress policy blocked most vendor newsrooms, academic publishers and community sites (apple.com, blog.google, about.fb.com, nvaccess.org, afb.org, nfb.org, acb.org, applevis.com, doubletaponair.com, arxiv.org, dl.acm.org, Substack, Reddit, Mastodon, Hacker News, YouTube, forum.cursor.com, lovable.dev, codeium.com, openai.com). What this means for coverage:

- GitHub-based evidence is over-represented. GitHub issues, READMEs, changelogs, release pages, npm/PyPI metadata, code.claude.com, support.claude.com, developer.apple.com and microsoft.com were the only reliably fetchable primary sources, so the brief is strongest on open source, on Claude Code, Codex, Copilot CLI, VS Code and NVDA, and on blind developers who file issues. It is weakest on JAWS, Orca, commercial no-code builders, consumer apps and anything that happens only on vendor sites.
- Community forums, podcasts and blind-authored articles were seen mostly through search-engine snippets or through Jamal Mazrui's dated, link-checked directory; quotes from AppleVis, AFB and Double Tap are therefore near-verbatim but unread in full, and exact thread dates are often unconfirmed. Reddit r/Blind, Mastodon, program-l (April–October), Hacker News and LinkedIn were not read at all.
- Academic papers were verified at the level of title, authors, venue, date and abstract from search snippets and companion repositories; full texts were not read, so detailed results marked "not retrieved" remain so. Conferences whose accepted-paper lists were not reachable (ASSETS 2026, UIST 2026, W4A 2026, ICCHP 2026) may contain relevant work not listed here.
- Vendor newsrooms were unreachable, so dates for Apple, Google, Meta, Be My Eyes and OpenAI announcements rest on press coverage; where coverage conflicted, the brief gives the conservative date.
- Several products are represented by their GitHub repository creation or push dates rather than releases; those are flagged in the text. Star counts and "not tested with blind users" admissions are reported as the projects state them.
- Negative findings ("nothing found for Bolt, v0, Replit, Stripe, Shopify, accelerators for blind founders") mean nothing surfaced through these channels, not that nothing exists.
